# Functions unreachable from the production `main` packages.
#
# WHY THIS FILE EXISTS. `golangci-lint` runs with defaults and its `unused` check
# does NOT report EXPORTED identifiers -- it assumes another package may call
# them. So an exported function whose only caller is deleted stays green forever.
# Measured: `RecordClaimLeafStats` was written 2026-04-20, its only caller went
# away with claim_pipeline.go on 2026-06-24, and for four months the linter, CI
# and the repo's own metric check all passed while docs/CLAIM_LEAF_MODEL.md told
# operators to watch a counter that could not move.
#
# A TEST IS NOT A CALLER. `deadcode` runs with the production mains as roots and
# test files excluded, on purpose.
#
# HOW TO USE IT. Every line is one function that is knowingly unreachable, with
# the reason. If you cannot write the reason, the answer is to delete the
# function or wire it up. A function in the scan and NOT here fails the gate.

# --- TEST SEAMS -----------------------------------------------------------
# These exist so a test can OBSERVE or FORCE something production does on its
# own schedule. That is not the self-deception this gate hunts: the deception is
# a PRODUCT function alive only because its test calls it, which is what
# RecordClaimLeafStats was. Each line below has a real test exercising it, named.
#
# The honest alternative is to move them behind `//go:build test`. They are kept
# here instead because the move is a bigger change than the problem, and because
# a seam that is DECLARED is not a seam that deceives.
# TxWindowFrom is not a seam added FOR a test: it is the missing half of a pair
# that shipped half-declared. WithTxWindowTimeout has been exported since it
# existed and the context key is private, so a budget could be written into a
# context from anywhere and read back from nowhere. That made "the budget
# travelled" impossible to EXPRESS outside tx, not merely hard to check -- which
# is why nothing ever asserted it. effectiveTxTimeout cannot be its production
# caller: it needs the whole txWindow including computedAt, and routing it through
# here to look wired would be dressing a seam up as a refactor. That today's only
# caller lives in another package is the consequence of the defect, not its cause.
tx/tx_client.go TxWindowFrom                                    # reads the window budget a context carries; the writer was always public and the reader was not (tx/tx_window_from_test.go)
keys/keyring_provider.go NewKeyringProviderWithKeyring          # injects a prepared keyring; production builds its own (keys/keyring_provider_test.go)
observability/runtime_metrics.go RuntimeMetricsCollector.CollectNow  # forces a collection that production does on a ticker (observability/runtime_metrics_test.go)
observability/runtime_metrics.go RuntimeMetricsCollector.LastMallocs # reads collector state a test asserts on (observability/runtime_metrics_test.go)
observability/server.go Server.IsRunning                        # lets a test observe lifecycle without racing on the listener (observability/server_test.go)
# KEPT ON PURPOSE THOUGH IT IS NO LONGER REPORTED (2026-09-12, item 224). deadcode
# stopped listing this one when the shutdown drain landed, and `deadcode -whylive`
# answers why: "reachable only through reflection". That is a category deadcode
# excludes from its dead list, so the function was NOT wired up -- a reflection edge
# now reaches it and the scan simply stops mentioning it. Its only real caller is
# still a test (relayer/proxy_simulation_test.go), and the gate runs deadcode
# without -test.
#
# Kept because that edge is incidental: if it goes, the function is reported again,
# and an allowlist missing its entry turns that into a gate failure reading "new
# unreachable function" -- a confusing failure for whoever receives it. Keeping it
# costs the gate nothing. Note the general shape, which is worth more than this one
# entry: deadcode's dead list SHRINKS SILENTLY when a reflection edge appears, so a
# genuinely dead function can stop being reported without anyone touching it. The
# check that sees that drift is `comm -13`, which static.sh does not run (item 209).
relayer/simulation.go SimulationVerifier.Reload                 # reconfigures the verifier between cases; production wires it once via SetSimulationVerifier and has NO hot-reload path, so changing simulation config needs a restart (relayer/simulation_test.go, 6 uses)

# --- TRANSITIONAL: the I4 BatchingPublisher arrives UNWIRED on purpose ---
# These entries are not permanently dead code: they are the batch mechanism, written and verified
# with teeth of its own, committed BEFORE its wiring because the wiring is a behaviour change on
# the data path that needs its own -- the order of the final flush against the Redis client's
# Close(), a convention rule that freezes that order, and the knob's validation. Committing both
# halves together would have produced a commit that turns on a switch whose metrics LIE.
#
# No count is written here on purpose: the sentence that adds an entry is exactly the one that
# keeps stating the old total, and this header already said "twelve" while listing sixteen.
#
# THESE LINES ARE DELETED by the commit that wires the BatchingPublisher into cmd/cmd_relayer.go.
# It has to be remembered, because NOTHING will say so: static.sh runs `comm -23 scan allowlist`,
# which reports what is in the scan and not in the allowlist -- an entry that has stopped being
# unreachable is tolerated in silence. This comment used to assert the opposite ("deadcode will
# report them as leftovers") and that was false, which is the worst kind of wrong to leave here:
# it tells the next reader not to look.
transport/redis/batching_publisher.go NewBatchingPublisher            # built by the wiring, which lands in the next commit

transport/redis/batching_publisher.go BatchingPublisher.Close         # flushes what is queued at shutdown; called by the wiring's defer
transport/redis/batching_publisher.go BatchingPublisher.run           # the dispatcher loop, started by NewBatchingPublisher
transport/redis/batching_publisher.go BatchingPublisher.dispatchAll   # empties the queue chunk by chunk; called by run and by the final flush
transport/redis/batching_publisher.go BatchingPublisher.finalFlush    # the shutdown flush, on a context detached from the process cancellation
transport/redis/batching_publisher.go BatchingPublisher.takeChunk     # cuts the next chunk without splitting a stream across two
